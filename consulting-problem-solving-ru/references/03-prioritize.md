# Шаг 3: приоритизация

Определи, какие ветки важнее всего — куда направить аналитические усилия для максимума инсайта. Анализировать всё одинаково невозможно и не нужно.

## Фаза INPUT

1. «Где, по твоему ощущению, лежит наибольший эффект?»
2. «Есть ветки, которые ты хочешь анализировать вне зависимости от фреймворка?»
3. «Есть ветки, ответ по которым ты уже знаешь?»
4. «К каким данным у тебя есть лёгкий доступ? Что было бы трудно достать?»
5. «Какие ветки явно поставить в парковку?»

Предложенные пользователем приоритеты имеют большой вес — не штампуем не глядя, но это сильный сигнал.

## Артефакт: документ матрицы приоритетов (.md)

Содержит: приоритетную оценку каждой ветки, фокус-области (2–3 для глубокого анализа), парковку с обоснованиями, рекомендации по распределению ресурсов.

## Фреймворк Impact × Feasibility

По каждой ветке оцени:

**Impact (влияние)** (высокий/средний/низкий): насколько решение этой ветки сдвинет стрелку?
**Feasibility (реализуемость)** (высокая/средняя/низкая): можем ли мы получить полезные ответы при текущих ограничениях?

| | Высокий импакт | Средний импакт | Низкий импакт |
|--|------------|---------------|------------|
| **Высокая реализуемость** | **P1** — делаем первым, глубоко | P2 — если позволит время | Пропустить |
| **Средняя реализуемость** | **P1** — стоит усилий | P3 — только если критично | Пропустить |
| **Низкая реализуемость** | P2 — ищем прокси | Пропустить | Пропустить |

**Сигналы высокого приоритета**: большая доля от целого, недавнее изменение, высокая дисперсия по сегментам, акцент стейкхолдера, сильная гипотеза, явно отмечено пользователем.

**Сигналы депрерости**: малая величина, уже хорошо понятно, вне скоупа, недостижимые данные / влияние.

## Шаблон вывода

```markdown
# Приоритизация: [ключевой вопрос]

## Оценка приоритетов
| Ветка | Импакт | Реализуемость | Приоритет | Обоснование |
|-------------|--------|-------------|----------|-----------|
| [Ветка] | Высокий | Высокая | **P1** | [Почему] |

## Фокус-области (глубокий анализ)
### 1. [Топ-приоритет]
- **Почему**: [1–2 предложения]
- **Гипотеза для проверки**: [с шага 2]
- **Оценка усилий**: [грубое ощущение]

## Парковка
- [Ветка X]: [почему депрерована]

## Импликации для плана работ
[Короткая заметка, что это означает для шага 4]
```

## Фаза REVIEW

Покажи предложенную приоритизацию, явно сравни с вводными пользователя, подтверди доступность данных по веткам P1, подтверди парковку. **Не переходи к шагу 4 без явного утверждения.** Если пользователь меняет приоритеты — даже вопреки фреймворку — вноси правки. Суждение партнёра по приоритетам — окончательное.

## Ловушки

- **Всё P1**: если P1-пунктов больше 3–4 — приоритизация не сделана, форс-ранжируй
- **Лёгкое над важным**: высокая реализуемость + низкий импакт — ловушка
- **Депреризация без вопроса**: никогда не паркуй ветку без согласия пользователя
- **Игнор вводных пользователя**: если партнёр сказал, что это важно — это важно
