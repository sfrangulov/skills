# Шаг 8: коммуникация

Упакуй всю работу в убедительный артефакт. Лучший анализ ничего не стоит, если его не сообщить ясно.

У этого шага два трека с **разными правилами контента**:
- **Слайды** *(по умолчанию)*: дистилляция, одно сообщение на слайд. Прочитай `08-slides-content.md` — правила контента. Этот скил производит **контент слайдов** — утверждённый контент передаётся скилу-сборщику (html-slide-deck-editor, pptx и т.п.) для визуального рендеринга.
- **Вертикальный документ**: нарративная проза, глубина секций, более длинные доказательные цепочки. Прочитай `08-vertical-content.md` — правила контента. Этот скил производит **утверждённый контент** — скил-сборщик (docx и т.п.) занимается форматированием и стилизацией дальше.

Спроси пользователя, какой формат он хочет, до начала работы (по умолчанию — HTML-слайды). Затем читай **только** соответствующий файл с правилами контента.

## Фаза INPUT: собери предпочтения по нарративу и структуре

Используй **AskUserQuestion** для сбора структурированных выборов в 2 пакетах (до 4 вопросов в каждом).

### Пакет 1: нарратив, заголовок

**Q1 — Нарративная структура** (header: «Narrative», multiSelect: false):
1. **Answer-First (Пирамида)** — открой выводом, поддерживай аргументами, потом доказательства. Подходит: согласованные / старшие / ограниченные по времени аудитории.
2. **Evidence-First (Build)** — наблюдения → паттерн → вывод. Подходит: скептичные аудитории, контринтуитивные выводы.
3. **Narrative Arc (SCR)** — Situation → Complication → Resolution (ситуация → осложнение → развязка). Подходит: убеждение, аудитории, которым нужно сначала прочувствовать проблему.
4. **Transformation (Текущее → Будущее → Мост)** — as-is → to-be → путь. Подходит: управление изменениями, vision-setting.
5. **Comparative Evaluation (Опции → Критерии → Рек.)** — альтернативы → оценка → выбор. Подходит: решения совета, выбор поставщика.
6. **Sequential / Process (Step-by-Step)** — временной/логический порядок. Подходит: планы внедрения, проектные апдейты.

**Q2 — Заголовок и подзаголовок** (header: «Title»): автогенерация из постановки проблемы или ввод пользователя.

### Пакет 2: структура, кол-во страниц, приложение

**Q3 — Executive summary** (header: «Exec Summary»): да (рекомендуется) / нет.

**Q4 — Контекст и цели** (header: «Context»): да (рекомендуется) / нет.

**Q5 — Контентные страницы** (header: «Page Count»): компактно (4–6) / стандарт (8–12) / расширенно (15–20) / пользовательское. Счёт исключает титульный лист, exec summary и слайды/страницы контекста.

**Q6 — Приложение** (header: «Appendix»): да (рекомендуется) / нет.

### Уточняющие вопросы (разговорно, после структурированных)

1. **Аудитория**: кто, какой уровень, что знают
2. **Ключевое сообщение**: одна вещь, которую нужно запомнить
3. **Тон**: смело / решительно vs. осторожно / по опциям
4. **Чувствительный контент**: что фреймировать аккуратно или вынести в приложение

## КРИТИЧНО: никаких буквальных ярлыков фреймворка

**Никогда не используй терминологию фреймворка как заголовки слайдов, секций или ярлыки.** Фреймворки задают структуру — аудитория видит только контекстный контент.

Вместо «Situation» → опиши реальный контекст. Вместо «Complication» → опиши реальное нарушение. Вместо «Resolution» → опиши конкретное решение. Вместо «Current State» / «Future State» / «Bridge» → опиши, что происходит, видение и путь.

**Исключение**: «Executive Summary» — стандартный навигационный ярлык, его можно оставить.

## Плейбуки нарративных структур

У каждого плейбука два варианта: **последовательность слайдов** (для трека слайдов) и **план секций** (для вертикального трека).

### 1. Answer-First (Пирамида)
**Дуга**: вывод → опорные аргументы → доказательства

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> ОТВЕТ (основная рек.) -> Аргумент 1 + доказательства -> Аргумент 2 + доказательства -> Аргумент 3 + доказательства -> Внедрение / следующие шаги -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Рекомендация (секция) -> Аргумент 1 (секция с под-секциями для доказательств) -> Аргумент 2 -> Аргумент 3 -> Дорожная карта внедрения -> [Appendix]
```

### 2. Evidence-First (Build)
**Дуга**: наблюдения → паттерн → вывод

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> Наблюдение 1 -> Наблюдение 2 -> Наблюдение 3 -> Паттерн / инсайт -> Импликация -> Рекомендация -> Следующие шаги -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Ключевые наблюдения (секция на наблюдение с поддерживающими данными) -> Паттерн (секция синтеза) -> Импликации -> Рекомендация -> Следующие шаги -> [Appendix]
```

### 3. Narrative Arc (SCR)
**Дуга**: ситуация → осложнение → развязка

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> Базовый контекст (2 слайда) -> Нарушение + ставки (2 слайда) -> Ключевой инсайт -> Рекомендация -> Конкретные инициативы -> Квантифицированная польза -> Следующие шаги -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Ландшафт (2–3 страницы базового состояния) -> Что изменилось (нарушение, доказательства, ставки) -> Путь вперёд (инсайт + рекомендация) -> Инициативы в деталях -> Ожидаемый эффект -> Следующие шаги -> [Appendix]
```

Используй контекстные заголовки — никогда не подписывай секции «Situation», «Complication», «Resolution».

### 4. Transformation (Текущее → Будущее → Мост)
**Дуга**: как сейчас → каким должно быть → как туда добраться

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> Реальность сегодня + что сломано -> Видение + как выглядит «хорошо» -> Путь (инициативы) -> Дорожная карта -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Где мы сегодня (детальное текущее состояние) -> Куда нам надо (видение с конкретикой) -> Как мы туда дойдём (инициативы, фазирование, ответственные) -> Дорожная карта и вехи -> [Appendix]
```

Никогда не используй «Current State», «Future State», «Bridge» как ярлыки.

### 5. Comparative Evaluation
**Дуга**: альтернативы → оценка → выбор

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> Альтернативы (по 1 слайду) -> Подход к оценке / критерии -> Сравнительные результаты -> Почему победитель побеждает -> Риски -> Внедрение -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Обзор опций -> Опция A (детальная секция) -> Опция B -> Опция C -> Фреймворк оценки и критерии -> Сравнительный анализ -> Рекомендация и обоснование -> Риски и митигации -> Внедрение -> [Appendix]
```

### 6. Sequential / Process
**Дуга**: фаза 1 → фаза 2 → ... → фаза N

**Последовательность слайдов**:
```
Title -> [Exec summary] -> [Context] -> Обзор (фазы единым кадром) -> Фаза 1 + детали -> Фаза 2 + детали -> ... -> Зависимости / риски -> Таймлайн / ресурсы -> [Appendix]
```

**План секций**:
```
Title page -> [Exec summary] -> [Context] -> Обзор подхода -> Фаза 1 (детальная секция: активности, вехи, зависимости) -> Фаза 2 -> ... -> Сквозные риски и зависимости -> Ресурсы и таймлайн -> [Appendix]
```

## Ловушки

- **Тематические заголовки вместо action-titles**: «Выручка Q3» ничего не говорит (применимо к обоим трекам — слайды используют action-titles, вертикальный — сильные заголовки секций)
- **Неправильная структура для аудитории**: Evidence-First для CEO, у которого мало времени, — ошибка
- **Сборка вокруг чисел**: цифры подчёркивают тезисы, не строят их. Если слайд / секция бессмысленны без чисел — переписывай вокруг инсайта
- **Дряблая проза**: применяй Strunk & White безжалостно
- **Обнажение каркаса фреймворка**: никогда не используй буквальные ярлыки фреймворка как заголовки
- **Пропуск гейтов**: все гейты должны пройти по порядку до начала сборки
- **Правила слайдов для документов или наоборот**: у каждого трека свой контентный файл — читай и следуй нужному
