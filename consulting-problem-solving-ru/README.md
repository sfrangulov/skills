# Consulting Problem Solving (русская версия)

**Скил для Claude Code, превращающий Claude в твоего консалтингового ассоциата.**

Дай ему запутанную бизнес-задачу. Получи структурный анализ, рекомендации на основе доказательств и готовые к презентации артефакты — построенные по той же методике, что используют ведущие стратегические консалтинговые фирмы.

---

## Как это работает

Ты играешь роль **консалтингового партнёра** — лицо, принимающее решения, с доменной экспертизой.
Claude играет роль **консалтингового ассоциата** — приносит аналитические фреймворки, структурное мышление и исполнение.

Каждый шаг идёт по одному ритму: ты задаёшь направление, Claude строит, ты проверяешь и утверждаешь, прежде чем двигаться дальше. Ничто не идёт вперёд без твоего явного одобрения.

### 8-шаговый процесс

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ 1. Определи  │─▶│ 2. Структура │─▶│ 3. Приори-   │─▶│ 4. План работ│
│   проблему   │  │   (MECE)     │  │   тизация    │  │              │
└──────────────┘  └──────────────┘  └──────────────┘  └──────┬───────┘
       РАМКА ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┼ ─ ─ ─
                                                             │
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────▼───────┐
│8. Коммуника- │◀─│ 7. Рекомен-  │◀─│ 6. Синтез    │◀─│ 5. Анализ    │
│   ция        │  │    дации     │  │              │  │              │
└──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘
   ДОСТАВКА             ◀─  ─  ─  АНАЛИЗ  ─  ─  ─  ─  ─  ─  ─  ─
```

Можно прогнать весь процесс end-to-end или вызвать любой шаг отдельно.

### Шаг 1: определение проблемы

> *Артефакт: постановка проблемы (`.md`)*

Правильно сформулированная проблема — половина решения. Claude просит описать ситуацию, что значит «успех», что в скоупе и вне его, ключевые ограничения и любые начальные гипотезы. Из ответов Claude извлекает **точный ключевой вопрос (key question)** — одно предложение, на которое ответит весь проект, — и собирает документ постановки проблемы: контекст, границы скоупа, критерии успеха, стейкхолдеры, ограничения.

Это самый важный шаг. Хорошо сформулированный вопрос предотвращает недели анализа, направленного не туда.

**Ты даёшь:** ситуацию своими словами, что значит «решено», границы, догадки.
**Claude производит:** структурированную постановку проблемы, привязанную к одному ключевому вопросу. Ты проверяешь и утверждаешь, прежде чем что-либо стартует.

---

### Шаг 2: структурирование проблемы

> *Артефакт: дерево проблемы (`.md` + опционально `.svg`)*

Claude декомпозирует ключевой вопрос в **дерево проблемы (issue tree)** — иерархическую разбивку, где каждый уровень MECE (Mutually Exclusive, Collectively Exhaustive — взаимоисключающе и совместно исчерпывающе). Без пересечений, без пробелов.

Ты выбираешь фреймворк декомпозиции, или Claude предлагает один на основе типа задачи:

| Фреймворк | Когда подходит |
|:----------|:---------|
| **Прибыльность** (выручка vs. затраты) | Сжатие маржи, диагностика P&L |
| **Выход на рынок** (привлекательность vs. способность vs. экономика) | Оценка нового рынка или сегмента |
| **Операционные улучшения** (быстрые победы vs. среднесрочные vs. структурные) | Эффективность и процессные задачи |
| **Клиенты / рост** (текущие vs. новые клиенты vs. новые продукты) | Стратегия роста, удержание |
| **Кастомный** | Всё, что не укладывается в стандартные рамки |

Каждая крупная ветка получает **тестируемую гипотезу** — конкретное опровергаемое утверждение, которое анализ подтвердит или опровергнет. Дерево обычно идёт на 2–3 уровня вглубь с явной MECE-проверкой на каждом уровне.

---

### Шаг 3: приоритизация

> *Артефакт: матрица приоритетов (`.md`)*

Не каждая ветка дерева заслуживает равного внимания. Claude помогает оценить каждую ветку по двум измерениям:

- **Влияние (Impact)**: насколько решение этой ветки сдвинет стрелку по ключевому вопросу?
- **Реализуемость (Feasibility)**: можем ли мы реально это исследовать с имеющимися данными, временем и ресурсами?

Ветки ранжируются по приоритетам:

| Тир | Критерий | Действие |
|:-----|:---------|:-------|
| **P1** | Высокое влияние + высокая/средняя реализуемость | Исследуем глубоко |
| **P2** | Высокое влияние + низкая реализуемость, или среднее + высокая | Ищем прокси или откладываем |
| **P3+** | Более слабые комбинации | Паркуем с обоснованием |

На выходе обычно 2–4 фокус-области уровня P1. Если их больше — приоритизация не доделана. Ничто не паркуется без явного согласия пользователя, и в парковке сохраняется обоснование, чтобы можно было вернуться.

---

### Шаг 4: построение плана работ

> *Артефакт: план работ (`.xlsx`)*

Claude переводит приоритетные ветки в конкретный аналитический план — таблицу с тремя листами:

**Лист Summary** — название проекта, ключевой вопрос, обзор воркстримов.

**Detailed Analysis Plan** — каждая строка — один анализ:

| Колонка | Назначение |
|:-------|:--------|
| Workstream | Какой ветке P1 служит |
| Analysis Name | Описательная метка |
| Question Answered | Конкретный вопрос, на который отвечает анализ |
| Approach | Количественный (тренды, сегментация, бенчмаркинг, финансовое моделирование) или качественный (best practice, картирование процесса, оценка рисков) |
| Data Needed | Какие входные данные нужны |
| Source | Откуда берутся данные |
| Dependencies | Какие другие анализы должны завершиться раньше |
| Hypothesis | Что ожидаем найти |

**Лист Data Inventory** — заранее выявляет пробелы в данных и обходные пути, чтобы они не вылезли в середине анализа.

Типовой проект — 15–25 анализов. Больше 30 — приоритизация недостаточна. Зависимости картируются, чтобы независимые анализы шли параллельно, а гейтящие — первыми.

---

### Шаг 5: проведение анализов

> *Артефакты: аналитический воркбук (`.xlsx`) + документ выводов (`.md`)*

Здесь делается аналитическая работа. По каждому анализу из плана Claude:

1. Формулирует вопрос, на который отвечает
2. Выполняет анализ (с твоими данными, или с явно отмеченными допущениями, если данных нет)
3. Применяет тест **«и что?» (so what?)** — что этот вывод значит для ключевого вопроса?
4. Оценивает гипотезу — **подтверждена**, **частично подтверждена** или **опровергнута**
5. Фиксирует уточняющие вопросы

**Качество данных контролируется жёстко:**

- Каждая цифра имеет источник (например, «Годовой отчёт компании за 2024», «Bureau of Labor Statistics», «Росстат»)
- Данные старше 18 месяцев в быстро меняющихся доменах помечаются
- Цифры перекрёстно проверяются на внутреннюю согласованность
- Когда данных нет, Claude никогда не оценивает молча — он представляет предлагаемые значения с обоснованием и диапазонами чувствительности (низкий / базовый / высокий)
- Две прочные перекрёстно проверенные точки данных лучше десяти слабо подтверждённых

**Аналитический воркбук** имеет сводный лист (одна строка на анализ с выводом и уровнем уверенности), детальные листы по анализам и лист допущений. **Документ выводов** — нарратив, связывающий выводы с ключевым вопросом, выявляющий темы и открытые вопросы.

---

### Шаг 6: синтез выводов

> *Артефакт: документ синтеза (`.md`)*

Синтез — не сводка. Сводка говорит «вот что мы нашли». Синтез говорит «вот что это всё **означает вместе**».

Claude раскладывает все выводы и ищет паттерны:

| Паттерн | Что означает |
|:--------|:-------------|
| **Сходящийся (Convergent)** | Несколько независимых выводов указывают в одну сторону — самая сильная база для действия |
| **Напряжение (Tension)** | Выводы указывают в разные стороны — синтез разрешает противоречие |
| **Последовательность (Sequencing)** | Выводы предполагают временную последовательность — сделай A до B |
| **Условный (Conditional)** | Ответ зависит от нерешённой переменной — рекомендации должны учесть оба сценария |

Выход следует чёткой структуре:

- **Ответ** — 1–2 предложения, ориентированные на решение, прямо отвечающие на ключевой вопрос
- **Логика поддержки** — 3–5 инсайтов, каждый подкреплён конкретными доказательствами с шага 5
- **Как кусочки сходятся** — нарративная нить, связывающая инсайты в связный аргумент
- **Что может нас опровергнуть** — таблица рисков с вероятностью, влиянием и митигацией для каждого
- **Оценка уверенности** — общая уверенность, сильнейшие и слабейшие места аргумента

Claude спрашивает твою интерпретирующую линзу: что бросается в глаза, что удивляет, как стейкхолдеры могут отреагировать, есть ли чувствительные места по фрейминг.

---

### Шаг 7: формулирование рекомендаций

> *Артефакт: бриф с рекомендациями (`.md`)*

Каждая рекомендация должна пройти тест **SMART+E**: Specific (конкретная), Measurable (измеримая), Actionable (применимая), Relevant (релевантная), Time-bound (с привязкой ко времени) и Evidence-backed (подкреплённая доказательствами).

Claude представляет **2–3 опции** до финализации — у каждой плюсы, минусы и ожидаемое влияние — и склоняется к одной с обоснованием, но решение принимаешь ты.

Утверждённая рекомендация структурируется так:

- **Основная рекомендация** — главное действие с обоснованием, оценкой влияния и уровнем уверенности
- **Поддерживающие рекомендации** (1–3) — каждая с пунктами «Что / Почему / Ожидаемое влияние / Сроки / Ответственный»
- **Дорожная карта внедрения** — фазированная, чтобы каждая стадия давала независимую ценность:

| Фаза | Сроки | Фокус |
|:------|:---------|:------|
| **Немедленные** | 0–3 месяца | Быстрые победы, набирающие импульс и доверие |
| **Ближнесрочные** | 3–12 месяцев | Структурные изменения с измеримым эффектом |
| **Среднесрочные** | 1–3 года | Трансформационные шаги, усиливающие ранние выигрыши |

- **Сводка по влиянию** — требуемые инвестиции, годовой эффект, окупаемость и уверенность по каждой рекомендации
- **Риски и митигации** — ожидаемые возражения («уже пробовали», «слишком рискованно», «слишком дорого», «политически сложно») с заготовленными ответами
- **Следующие шаги** — 3–5 конкретных действий с ответственными

Бриф также включает **слайд-готовое резюме** в приложении — императивные формулировки, эффект в одну строку, фазовые действия — готово для шага 8.

### Шаг 8: коммуникация

> *Артефакт: контент слайдов (`.md`) или контент вертикального документа (`.md`)*

Финальный шаг превращает анализ в убедительный нарратив. Ты выбираешь формат:

**Трек слайдов** — дистиллированные, сканируемые, одно сообщение на слайд. Action-titles (полные предложения, формулирующие инсайт, а не тематические ярлыки вроде «Анализ рынка»). Буллиты ограничены 12 словами. Таблицы и структурные элементы вместо стен текста. На каждом слайде с цифрами — футер с источником.

**Трек вертикального документа** — нарративная проза с полной глубиной аргумента. Заголовки секций двигают аргумент. Абзацы следуют контракту: тематическое предложение, доказательство (2–3 предложения), импликация. Активный залог, короткие предложения для ключевых тезисов, конкретный язык.

Оба трека проходят через **обязательную структуру гейтов**:

**Gate 1 — сториборд.** Claude представляет последовательность хедлайнов и нарративную структуру. Ты выбираешь из шести плейбуков:

| Плейбук | Структура | Когда подходит |
|:---------|:----------|:---------|
| **Answer-First** (Пирамида) | Вывод &rarr; Аргументы &rarr; Доказательства | Согласованные аудитории, старшие руководители, ограничение по времени |
| **Evidence-First** (Build) | Наблюдения &rarr; Паттерн &rarr; Вывод | Скептичные аудитории, которым нужно увидеть доказательства |
| **Narrative Arc** (SCR) | Ситуация &rarr; Осложнение &rarr; Развязка | Убеждение и поддержка |
| **Transformation** | Текущее состояние &rarr; Будущее состояние &rarr; Путь | Управление изменениями |
| **Comparative Evaluation** | Опции &rarr; Критерии &rarr; Победитель | Решения совета между альтернативами |
| **Sequential / Process** | Фаза 1 &rarr; Фаза 2 &rarr; ... &rarr; Фаза N | Планы внедрения |

Ты утверждаешь сториборд до того, как что-то будет написано.

**Gate 2 — скептическое ревью.** Отдельный ревью-агент стресс-тестит утверждённый сториборд против синтеза и рекомендаций. Он проверяет провалы здравого смысла, разрывы «и что?», адекватность цифр, логическую связность, склонность к свалкам данных и размытость рекомендаций. Результаты возвращаются как нумерованный список предлагаемых правок с тегами серьёзности (MUST FIX / SHOULD FIX / CONSIDER). Ты принимаешь или отклоняешь каждый пункт — ничто не меняется без твоего одобрения.

**Gate 2b — контент** (только для трека слайдов). Claude дистиллирует весь контент по правилам контента слайдов и сохраняет в папку проекта. Ты проверяешь и правишь до утверждения.

После прохождения всех гейтов утверждённый контент передаётся скилу-сборщику для визуального рендеринга и стилизации.

## В чём отличие

**Ты остаёшься у руля.** Claude не исчезает в чёрный ящик и не возвращает 40-страничный дек. На каждом шаге ты даёшь вводные, проверяешь результат и утверждаешь, прежде чем что-то двинется дальше. Твоя доменная экспертиза формирует каждый артефакт.

**Синтез, не сводка.** Шаг 6 не просто перечисляет выводы — он сплетает их в связный аргумент. «Вот что это всё *значит вместе*» принципиально отличается от «вот что мы нашли».

**Сначала нарратив, не данные.** Аргументы строятся на инсайте и логике. Цифры усиливают тезис — не строят его. Каждый слайд должен иметь смысл, если убрать цифры.

**Встроенный скептицизм.** До сборки любого финального артефакта скептический ревью-агент стресс-тестит сториборд на логические разрывы, неподкреплённые тезисы, склонность к свалкам данных и размытость рекомендаций. Ты принимаешь или отклоняешь каждую предлагаемую правку.

**Полная трассируемость.** YAML-frontmatter связывает каждую рекомендацию через инсайты, выводы, анализы, ветки и исходный ключевой вопрос. Любой вывод можно дотянуть до его доказательной базы.

**Два трека выхода.** Выбирай между **треком слайдов** (дистилляция, одно сообщение на слайд, сканируемо) и **треком вертикального документа** (нарративная проза с полной глубиной аргумента) — у каждого свои контентные правила.

## Использование

Начни разговор с Claude Code и активируй скил естественным образом:

> «Помоги структурно подумать про стратегию выхода в Юго-Восточную Азию»

> «Мне нужен структурный подход, чтобы понять, почему падает удержание клиентов»

> «Собери мне дек с рекомендациями для совета: покупать ли TargetCo»

Или вызови напрямую:

> `/consulting-problem-solving-ru`

Claude настроит папку проекта, проведёт через каждый шаг и выдаст артефакты по пути.

### Триггер-фразы

Скил активируется на: *стратегический консалтинг, фреймворк решения проблем, дерево проблемы, дерево вопросов, MECE, гипотезо-ориентированный, принцип пирамиды, пирамида Минто, анализ 80/20, поиск первопричин, бизнес-кейс, стратегическая рекомендация, структурное мышление, структурный подход* — или просто попроси помочь системно разложить сложную задачу. Английские триггеры (*issue tree, MECE, hypothesis-driven, pyramid principle, 80/20 analysis, root cause analysis*) тоже работают.

## Пример рабочего процесса

**Ты:** «Мы теряем enterprise-клиентов в пользу конкурента, запустившегося полгода назад. Помоги понять, что происходит и что с этим делать.»

**Шаг 1** — Claude расспрашивает про контекст, скоуп и критерии успеха. Производит постановку проблемы, привязанную к точному ключевому вопросу.

**Шаг 2** — Ты выбираешь фреймворк декомпозиции (или Claude предлагает один). Проблема разбивается в MECE-дерево — например, *Продуктовые пробелы vs. Цены vs. Исполнение в продажах vs. Сильные стороны конкурента*.

**Шаг 3** — Вместе оцениваете, какие ветки имеют наибольшее влияние и наиболее реализуемы. Две-три становятся фокус-областями P1.

**Шаг 4** — Claude собирает план работ: 15–20 конкретных анализов, каждый привязан к вопросу, подходу и источнику данных.

**Шаг 5** — Анализы выполняются. Каждый вывод проходит «и что?»-тест и получает уровень уверенности. Гипотезы подтверждаются, частично подтверждаются или опровергаются.

**Шаг 6** — Выводы синтезируются в связный нарратив — не список, а аргумент.

**Шаг 7** — Фазированные рекомендации с оценкой эффекта, дорожной картой и митигацией рисков.

**Шаг 8** — Ты выбираешь слайды или документ. Claude строит сториборд, запускает скептическое ревью и производит готовый к презентации контент, который скил-сборщик (`pptx`, `docx`) превращает в полированный артефакт.

## Принципы

| Принцип | Что означает |
|:----------|:-------------|
| **Пользователь ведёт, Claude исполняет** | У тебя — доменная экспертиза и ответственность. У Claude — фреймворки и аналитическая строгость. |
| **MECE на каждом уровне** | Mutually Exclusive, Collectively Exhaustive — взаимоисключающе и совместно исчерпывающе. Без пересечений, без пробелов. Проверяется явно. |
| **Гипотезо-ориентированно** | Формулируем гипотезы рано, проверяем в анализе, разворачиваем при свидетельствах против. |
| **«И что?» (so what?) безжалостно** | Каждый вывод, каждый слайд, каждый абзац обязан отвечать: что это значит для решения? |
| **Жёсткий 80/20** | Фокус на 20% вопросов, дающих 80% эффекта. Если P1-пунктов больше 3–4, ты не приоритизировал. |
| **Целостность данных** | Меньше цифр с высокой уверенностью лучше, чем много слабо подтверждённых. Каждая цифра — с источником. |
| **Консалтинговая проза** | Strunk & White интегрирован на каждом шаге. Активный залог, точный язык, без лишних слов. |

## Интеграция с другими скилами

Этот скил отвечает за **контент и структуру**. Визуальный выход не производит. После шага 8 передавай утверждённый контент скилу-сборщику для рендеринга:

- **Слайды** &rarr; `pptx`, `html-landing-page` или похожий конструктор деков
- **Документы** &rarr; `docx`, `pdf` или похожий конструктор документов
- **Стилизация** &rarr; `theme-factory` или `brand-guidelines` для визуальной идентичности
